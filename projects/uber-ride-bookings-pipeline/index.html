Uber Ride Bookings Data Engineering Pipeline

Raw ride-booking data is messy. I built a Medallion pipeline that prepares it for SQL analysis of bookings, revenue, cancellations and vehicle performance.

3Medallion layers: Bronze, Silver, Gold
4Gold areas: bookings, revenue, cancellations, vehicles
DeltaLake tables for each layer

Problem

Ride-booking data arrives with missing values, duplicates and quality issues, which makes it hard to analyze bookings, revenue, cancellations and vehicle performance reliably.

My role

I designed and built the pipeline on Azure Databricks, cleaned the data with PySpark, stored each layer as Delta Lake tables, and wrote the SQL on the Gold tables.

Result

Clean Gold tables that SQL queries can use directly to produce business insights on bookings, revenue, cancellations and vehicle performance.

Approach

Each layer has one job:

BronzeRaw ride-booking data as received
SilverPySpark fixes missing values, duplicates and quality issues
GoldDelta Lake tables for bookings, revenue, cancellations, vehicles

Data quality

Missing values, duplicates and other quality issues are handled in the Silver layer, so the Gold tables are ready to query.

Tools

  • Azure Databricks
  • PySpark
  • Apache Spark
  • Delta Lake
  • SQL
